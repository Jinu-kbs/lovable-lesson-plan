1. 중급으로 가는 길 — 무엇이 달라지나

초보 단계가 "내 컴퓨터의 폴더 하나를 정리하는 작업"이었다면, 중급은 내 컴퓨터 밖의 도구(Drive·Gmail·Slack·DocuSign 등)를 연결하고, 직무별 플러그인으로 Claude에게 일하는 방식을 가르치며, 예약 작업으로 반복 업무를 자동화하는 단계입니다.

핵심 4가지:

  1. 커넥터(Connectors) — 외부 SaaS·생산성 도구를 Cowork에 연결
  2. 직무별 플러그인(Plugins) — 재무·법무·HR·마케팅 등 업무 맥락을 주입
  3. 실전 워크플로우 — 여러 출처를 종합하는 다단계 업무 파이프라인
  4. 안전·검토 운영 — 인간 승인 루프(Human-in-the-loop)로 자동화의 위험 관리

권한이 커질수록 위험도 커집니다. 외부 도구를 연결한다는 것은 Claude가 내 메일·문서·캘린더에 접근할 수 있다는 뜻입니다. 이 교안의 4장(안전 운영)을 반드시 끝까지 읽으세요.

2. 커넥터 연결 — Drive·Gmail·Slack·DocuSign 등

2-1. 커넥터란

커넥터는 Cowork가 외부 도구·SaaS와 통신하도록 연결하는 다리입니다. 내부적으로는 MCP(Model Context Protocol) 방식으로 작동하며, 어떤 도구를 연결할지·얼마나 자주 권한을 물을지 사용자가 직접 통제합니다.

2026년 6월 기준 지원·언급된 주요 커넥터:

분류커넥터
생산성/문서Google Workspace(Drive·Gmail·Calendar), Microsoft 365
협업Slack, Jira
계약/문서DocuSign, LegalZoom
영업/세일즈Apollo, Clay, Outreach, Similarweb
금융/데이터FactSet, MSCI
기타WordPress, Harvey

커넥터 목록은 자주 늘어납니다. 게시 시점에 Settings → Connectors와 공식 릴리스 노트에서 실제 지원 목록을 재확인하세요.

2-2. 커넥터 연결 단계

  1. Claude 데스크톱 앱 → Settings → Connectors 진입
  2. 연결할 커넥터(예: Google Workspace) 선택 → Connect 클릭
  3. 해당 서비스 로그인·권한 승인 화면(OAuth)에서 접근 범위 확인 후 허용
  4. 권한 빈도 설정 — "매번 물어보기 / 이 세션 동안 허용" 등 선택
  5. Cowork 작업에서 자연어로 해당 도구 사용을 지시 (예: "내 Drive의 3분기 보고서 폴더를 요약해줘")
🖼️스크린샷Settings → Connectors 화면
✓ 체크포인트 연결한 커넥터 옆에 "Connected" 상태가 표시됨.

2-3. 커넥터 함정 (실무 주의)

Cowork는 격리된 VM/컨테이너 안에서 돌기 때문에, Google Workspace 등 일부 커넥터는 컨테이너 내부의 자격증명(credential) 처리 문제로 바로 안 붙을 수 있습니다. 실사용자 보고에 따르면:

  • 첫 연결 후 작업이 권한 오류로 멈출 수 있음 → 재인증 또는 권한 범위 재설정 필요
  • egress(외부 통신) 설정에 따라 일부 커넥터가 차단될 수 있음
  • 웹 검색·웹 가져오기(fetch) 도구는 서버 측에서 작동하므로 별도 커넥터 불필요
✓ 체크포인트 커넥터가 한 번에 안 붙어도 정상입니다. "Reconnect" 또는 권한 재승인을 먼저 시도하세요.

3. 직무별 플러그인 활용 — 재무·법무·HR·마케팅

3-1. 플러그인이란

플러그인은 Claude에게 일하는 방식, 사용할 도구·데이터, 핵심 워크플로우 처리법, 노출할 슬래시 명령(slash command)을 알려주는 묶음입니다. 팀이 같은 플러그인을 쓸수록 결과가 일관됩니다.

Anthropic은 2026년 1월 30일 사내 제작 11종 플러그인을 오픈소스로 공개했습니다. 직무별 카테고리:

직무플러그인 활용 예
재무(finance)분기 실적 데이터 추출, 비용 분석 리포트 초안
법무(legal)계약서 검토 체크리스트, 조항 비교
HR/운영(operations)채용 공고 초안, 온보딩 문서 정리
마케팅(marketing)캠페인 카피 초안, 경쟁사 리서치 종합
영업(sales)CRM 연동 잠재고객 리서치, 후속 연락 초안
데이터(data)비정형 문서 → 표/스프레드시트 변환

3-2. 플러그인 설치·커스터마이즈 단계

  1. Claude 데스크톱 앱 → Customize 섹션 또는 플러그인 마켓플레이스 진입
  2. 직무에 맞는 플러그인 검색·선택 후 설치
  3. 플러그인이 요구하는 커넥터(예: 재무 플러그인 ↔ FactSet)를 함께 연결
  4. 필요 시 플러그인의 지침·슬래시 명령을 우리 팀 프로세스에 맞게 커스터마이즈
  5. Team/Enterprise라면 조직 마켓플레이스로 공유
🖼️스크린샷플러그인 마켓플레이스 화면
✓ 체크포인트 설치한 플러그인의 슬래시 명령이 작업 입력창에서 자동완성으로 뜸.

플러그인 마켓플레이스는 2026년 2월 24일 정식 출시되며 Team/Enterprise 관리자 제어가 추가되었습니다. 초기에는 플러그인이 기기에 로컬 저장됐으나, 이제 조직 차원 공유가 가능합니다.

3-3. 글로벌 지침 + 예약 작업으로 일관성·반복 자동화

  • 글로벌 지침(Global Instructions): Settings → Cowork에서 선호하는 톤·형식을 입력·저장 → 모든 작업에 일관 적용
  • 예약 작업(Scheduled Tasks): 정기/온디맨드 작업 생성 (예: 매주 월요일 아침 주간 리포트 초안 자동 생성)
✓ 체크포인트 예약 작업을 만든 뒤, 지정 시각에 산출물이 생성됐는지 다음 날 확인하세요.

4. 안전·검토 운영 — 인간 승인 루프

이 장은 건너뛰지 마세요. 외부 도구를 연결한 순간부터 자동화의 편의와 위험이 함께 커집니다.

4-1. 두 가지 권한 모드

모드동작권장 상황
Ask before acting (행동 전 확인)Claude가 각 행동마다 멈추고 승인 요청새 커넥터·낯선 파일 — 기본 권장
Act without asking (확인 없이 실행)단계 사이에 멈추지 않고 빠르게 실행신뢰하는 파일·정의가 명확한 작업에만

"Act without asking"는 속도를 주지만, 프롬프트 인젝션 위험을 높입니다. 외부 문서·웹페이지에 숨은 악성 지시가 에이전트를 탈취할 수 있기 때문입니다.

4-2. 안전 가드레일과 한계

보호 장치:

  • 삭제 보호: 파일 영구 삭제 전 반드시 명시적 권한("Allow") 요구
  • 프롬프트 인젝션 탐지: 신뢰할 수 없는 콘텐츠가 들어올 때 서버 측 probe가 스캔, 탈취 시도로 보이면 경고 추가
  • 위험 작업 회피 훈련: 자금 이체·파일 삭제·민감 데이터 처리 회피
  • 헌법(Constitution) 기반: 모호한 상황에서 "진행 거부·명확화 요청"을 가정 행동보다 우선

알려진 한계(반드시 인지):

  • Anthropic 스스로 보호 장치가 "불완전(imperfect)"하다고 인정
  • "Ask before acting"는 소프트 경계 — 승인된 계획에서 벗어나는(drift) 사례 관찰됨
  • 승인 피로(approval fatigue): 습관적으로 "OK"를 눌러 실제 행동을 확인하지 않게 되는 현상
  • 간접 프롬프트 인젝션: 파일·웹사이트 내 악성 콘텐츠가 지시를 탈취할 위험

4-3. 규제 데이터 주의

Cowork는 GA 이후에도 규제 데이터(regulated data)에 대해 인증되지 않았습니다.

  • HIPAA Business Associate Agreement(BAA)에서 제외
  • 활동이 SOC 2 감사 로그에 포착되지 않음

의료·금융·정부 등 규제 데이터, 은행·민감 재무 문서에는 Cowork 접근 권한을 주지 마세요.

4-4. 인간 승인 루프 운영 체크리스트

  • 기본 모드는 항상 "Ask before acting"으로 둔다
  • 외부 커넥터 첫 연결 시 접근 범위(OAuth scope)를 최소로 승인
  • 삭제·전송·외부 공유가 포함된 작업은 단계마다 직접 검토
  • 승인 피로 경계 — "OK"를 누르기 전 Claude가 무엇을 하려는지 실제로 읽는다
  • 민감 폴더·앱(금융·의료·정부)은 커넥터로 연결하지 않는다

5. 실전 업무 워크플로우 예시

5-1. 워크플로우 A — 여러 출처 리서치 종합

목표: 흩어진 자료(Drive 문서 + 웹 검색)를 한 편의 요약 보고서로.

  1. Google Workspace 커넥터 연결 (2장)
  2. 작업 지시: "내 Drive '시장조사' 폴더의 문서들과 최신 웹 자료를 종합해 2페이지 요약을 만들어줘"
  3. Claude가 계획(plan)을 먼저 제시 → 검토 후 승인
  4. 개별 검색·문서 읽기 다단계 수행 (실사용 사례에서는 한 작업에 검색 수십 회 실행)
  5. 산출물 검토 → redirect/refine으로 다듬기
✓ 체크포인트 최종 요약의 인용·수치가 원본 문서와 일치하는지 직접 대조.

5-2. 워크플로우 B — 비정형 문서 → 스프레드시트 (재무 플러그인)

목표: 영수증 스크린샷·청구서 PDF를 경비 정산 표로.

  1. 재무 플러그인 설치 (3장)
  2. 대상 폴더 연결 + 작업 지시: "이 폴더의 영수증들을 날짜·항목·금액 컬럼의 스프레드시트로 정리해줘"
  3. Claude가 추출·표 생성 → 합계·분류 자동화
  4. 결과 검증 후 필요 시 회계 시스템에 직접 입력
✓ 체크포인트 추출된 금액 합계가 원본 영수증 총액과 맞는지 표본 검증.

5-3. 워크플로우 C — 주간 리포트 자동화 (예약 작업 + Slack)

목표: 매주 월요일 주간 현황 리포트를 자동 초안 생성.

  1. 예약 작업 생성 (3-3절): 매주 월요일 오전 9시
  2. 지시: "지난 주 Jira 완료 이슈와 Drive 진행 노트를 모아 주간 리포트 초안을 작성해줘"
  3. Team/Enterprise라면 Slack 통합으로 채널에서 직접 @Claude 태그로 위임·공유 (2026년 6월 추가 기능)
  4. 사람은 초안을 검토·보완만 수행
✓ 체크포인트 자동 생성된 초안을 그대로 배포하지 말고, 발행 전 반드시 사람이 검토.

6. 다음 단계

중급 과정을 마쳤다면:

  • 개발자편으로 진행 → 커스텀 플러그인 제작, MCP 직접 연동, 샌드박스 아키텍처, 기업 배포·관측성(RBAC·OpenTelemetry)
  • 직무 플러그인을 우리 팀 프로세스에 맞게 커스터마이즈해 마켓플레이스로 공유
  • 예약 작업을 늘려 반복 업무 파이프라인 구축 (단, 인간 승인 루프 유지)
